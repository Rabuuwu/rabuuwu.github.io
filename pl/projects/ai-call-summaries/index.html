Problem i użytkownicy

Dokumentowanie rozmowy wymagało czasu po jej zakończeniu. Zająłem się zamianą nagrań w tekst i podsumowania, które pracownicy mogą odczytać w CRM. Z rozwiązania korzysta cała firma.

Mój zakres, krok po kroku

  • Odpowiadałem za dostęp do nagrań rozmów.
  • Do transkrypcji wykorzystałem faster-whisper.
  • Samodzielnie zbudowałem API integracji.
  • Samodzielnie przeprowadziłem fine-tuning lokalnego modelu językowego.
  • Podsumowania generował lokalny LLM.
  • Zaimplementowałem wyświetlanie podsumowań w CRM.

Jak łączą się elementy

Proces rozdziela transkrypcję, podsumowanie i interfejs CRM. faster-whisper tworzy transkrypcję, lokalny LLM generuje podsumowanie, a moje API łączy wynik z CRM.

Integracja korzysta z endpointów JSON z uwierzytelnianiem tokenowym. Moja praca obejmowała zarówno połączenie systemów, jak i prezentację wyników pracownikom.

Praca z lokalnym modelem

Dostroiłem lokalny LLM i zintegrowałem generowane przez niego podsumowania z CRM. Połączyłem wyniki modelu z API i interfejsem używanym przez pracowników.

Rezultat i sposób porównania

Proces jest zintegrowany z CRM. W repozytorium nie ma odtwarzalnych pomiarów przed i po zmianie, dlatego nie przedstawiam liczbowego wyniku wydajności.

Użycie i granice opisu

Rozwiązanie jest używane w całej firmie. W opisie pokazuję swoją pracę i przepływ systemu, bez publikowania nagrań, danych klientów ani kodu firmowego.

The problem and users

Documenting a call required time after the conversation. I worked on turning recordings into text and summaries that staff can read inside the CRM. The solution is used across the company.

My responsibility, step by step

  • I handled access to the call recordings.
  • I used faster-whisper for transcription; I did not write the transcription model.
  • I built the integration API myself.
  • I fine-tuned the local language model.
  • The local LLM generated summaries.
  • I implemented the display of summaries in the CRM.

How the pieces connect

The workflow separates transcription, summarisation and the CRM interface. faster-whisper produces the transcript, a local LLM generates the summary, and my API connects the output with the CRM.

The integration uses JSON endpoints with token-based authentication. My work included both the connection between systems and the presentation of the results to staff.

Working with the local model

I fine-tuned the local LLM and integrated its generated summaries with the CRM. This is practical work with an existing model and its output, rather than a claim that I built a language model from scratch.

Result and measurement

I estimate that call documentation went from about 3 minutes to about 15 seconds. I derived the estimate by comparing average times. It describes documentation time, not the duration of the entire transcription and inference pipeline.

Use and publication boundary

The solution is used across the company. This case study describes my work and the system flow without publishing recordings, customer data or company code.

Why I started

During sessions with friends, we used paper character sheets and notebooks. Information was lost, some notes were hard to read, and replacing a notebook meant copying everything again.

We usually have a phone with us. I created an application to keep the information needed during a game in one place: the character, equipment, statistics, notes and campaign.

What is implemented

  • Create, edit and delete characters, with statistics and formula-based calculations.
  • Equipment with quantities, descriptions, categories, order and quick slots.
  • Text notes and a drawing canvas with zoom and panning.
  • Private messages between users who are friends, with notifications.
  • Campaign membership with a selected character; DM and co-DM management tools.

My project and its structure

I created D&D Companion around the needs of our RPG sessions. The current project includes a shared client, an API, database migrations and deployment configuration.

The client is JavaScript with Vite and Capacitor. It can be built as a PWA and for native mobile projects. A separate Expo preview exists for development; it is not the production client.

Data and permissions

The Express API stores data in PostgreSQL. Character records have an owner and flexible sheet data in JSONB. Campaign membership links a user with the character selected for that campaign.

The API checks character ownership. Campaign management is restricted to the owner or a co-DM. DM tools include member and character views, private notes and adding equipment. These checks are performed by the API, not just by hiding controls in the interface.

One client, a separate API

The PWA and mobile client communicate with the Node.js / Express API. PostgreSQL handles persistent records. Authentication uses passwords hashed with bcrypt, access tokens and refresh tokens.

The relational model keeps ownership and membership explicit while JSONB supports flexible character data.

Deployment and current state

The PWA is published on GitHub Pages and its public login screen is accessible. The current repository configures the API and PostgreSQL on Render, and GitHub Releases contains an Android package.

The project remains in development. Native iOS project files do not imply an App Store release. I link the public PWA and source repository without claiming production uptime or a number of active players.
